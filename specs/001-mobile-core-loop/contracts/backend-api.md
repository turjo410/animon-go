# Contract — Backend API (Supabase)

**Callers**: the mobile app, through `SupabaseGameRepository`. `LocalGameRepository` implements the same semantics in memory (research R14).

## Conventions

- **Auth**: every call needs the Supabase JWT of the signed-in user (anonymous accounts are allowed, R15). `player_id` is always `auth.uid()` and is never taken from the request body.
- **Reads**: direct `select` on own rows under RLS (`players`, `owned_companions`, `squad_members`, `journal_entries`, `encounters`, `battle_sessions`), or the `get_player_state` RPC for one consistent snapshot.
- **Writes**: only through the operations below. There are no direct table writes.
- **Idempotency**: every reward-affecting call takes a `request_id` (UUID v4) generated by the client once per user intent and reused on every retry. A repeated call returns **the original result**, with `"replayed": true`, and changes nothing.
- **Errors**: `{ "error": { "code": "<CODE>", "message": "<human text>" } }`. HTTP 4xx means do not retry; 5xx or a network failure means retry with the same `request_id`.
- **Response state**: every successful write response includes the updated `state` (the same shape as `get_player_state`), so the client never computes balances itself.

## Operations

### `bootstrap_player` — RPC
- **Request**: `{ request_id, timezone, display_name? }`
- **Effect**: creates the `players` row and grants the starter set **once** (ledger `bootstrap`): 3 starter companions, squad = those 3, 240 essence, 120 XP, and a welcome journal entry.
- **Response**: `{ state, replayed }`
- **Errors**: `INVALID_TIMEZONE`

### `get_player_state` — RPC (read-only)
- **Response**:

  ```json
  { "player": { "display_name": "...", "essence": 0, "xp": 0, "level": 1, "timezone": "..." },
    "roster": [ { "creature_id": "...", "level": 1, "bond": 15, "discovered_context": "...", "acquired_at": "..." } ],
    "squad": [ "id", "id", "id" ],
    "journal": [ { "id": "...", "title": "...", "detail": "...", "element": "...", "occurred_at": "..." } ],
    "trails": [ { "trail_id": "scan|bond|trial", "goal_met": true, "claimed_today": false, "reward": 30 } ],
    "server_time": "ISO-8601", "local_date": "YYYY-MM-DD" }
  ```

### `discover` — Edge Function `POST /functions/v1/discover`
- **Request**:

  ```json
  { "request_id": "uuid", "family": "feline", "confidence": 0.91,
    "attunement": "day|rain|night", "attunement_source": "simulated",
    "location": { "lat": 23.810, "lon": 90.412 } | null, "is_demo": false }
  ```

- **Validation**:
  - `family` is valid
  - `confidence` is at or above the server's threshold for that family (default 0.55)
  - `attunement_source == "simulated"`
  - `location`, when present, has ≤ 3 decimal places and is in range
- **Effect**: see data-model §5 (Discovery).
- **Response**:

  ```json
  { "creature_id": "solcat", "is_new": true, "familiarity": "newEncounter|probablyFamiliar|returningPresence",
    "rewarded": true, "essence_delta": 15, "xp_delta": 50, "state": { "...": "..." }, "replayed": false }
  ```

  `rewarded: false` means the daily discovery cap was reached. The companion is still added or levelled; only the essence and XP are withheld.
- **Errors**:
  - `LOW_CONFIDENCE` (400)
  - `INVALID_INPUT` (400)
  - `RATE_LIMITED` (429; 30 per hour)
- **UI copy rule (FR-008)**: familiarity text must never say or imply "same animal", "recognised" or "identified".

### `train_companion` — RPC
- **Request**: `{ request_id, creature_id }`
- **Effect**: in one transaction, deducts 30 essence, adds +1 level and bond +5 (capped at 100). Ledger `train:<request_id>`.
- **Response**: `{ creature_id, new_level, state, replayed }`
- **Errors**:
  - `NOT_OWNED`
  - `INSUFFICIENT_ESSENCE` (no partial deduction)

### `set_squad` — RPC
- **Request**: `{ creature_ids: [a, b, c] }`
- **Validation**: exactly 3 distinct IDs, all owned (FR-012).
- **Effect**: replaces all 3 squad rows atomically. Idempotent by nature, since setting the same squad twice is a no-op.
- **Response**: `{ state }`
- **Errors**:
  - `SQUAD_SIZE` (≠ 3 or duplicates)
  - `NOT_OWNED`

### `start_trial` — RPC
- **Request**: `{ request_id, wave }`, where `wave ≥ 1`
- **Validation**: the player's squad has exactly 3 members (SC-006).
- **Effect**: marks any earlier `active` session `abandoned`, then creates a `battle_sessions` row with `squad_snapshot` (IDs and current levels) and the enemy trio for that wave (R18). Idempotent on `request_id`: a repeat returns the same session.
- **Response**: `{ session_id, wave, allies: [{creature_id, level, max_hp}], enemies: [{creature_id, level, max_hp}] }`
- **Errors**: `SQUAD_SIZE`

### `complete-trial` — Edge Function `POST /functions/v1/complete-trial`
- **Request**: `{ session_id, actions: [ { "action": "basic|skill|heal|guard" } ... ] }`, with at most 500 actions
- **Effect**:
  1. Load the session (it must belong to the caller).
  2. Replay `actions` from the session's snapshot with the shared engine (R4/R19). A rejected action (on cooldown) is a no-op in the replay, exactly as on the client.
  3. **victory** → session = victory; ledger `wave:<session_id>` grants +60 essence and +100 XP; journal entry; trail `trial` goal met.
  4. **defeat** → session = defeat, no reward (FR-017).
  5. The replay still `active` when the actions run out → `INCOMPLETE_BATTLE` (400); the session stays active.
- **Response**: `{ outcome: "victory|defeat", rewarded: bool, essence_delta, xp_delta, state, replayed }`
- **Idempotency**: a terminal session returns its stored outcome with `replayed: true`. The reward is never granted twice (SC-004).
- **Errors**:
  - `SESSION_NOT_FOUND` (404)
  - `SESSION_ABANDONED` (409)
  - `INCOMPLETE_BATTLE` (400)

### `claim_trail` — RPC
- **Request**: `{ request_id, trail_id }`
- **Validation**: the goal is met for `local_date = (now() at time zone players.timezone)::date`, checked from the server's own encounters and sessions (R7/R17).
- **Effect**: ledger `trail:<trail_id>:<local_date>` adds the reward (30 / 40 / 60 essence).
- **Response**: `{ trail_id, local_date, essence_delta, state, replayed }`
- **Errors**:
  - `GOAL_NOT_MET`
  - `ALREADY_CLAIMED` (409, when the key exists under a *different* `request_id`)

### `set_timezone` — RPC
- **Request**: `{ timezone }`
- **Rule**: allowed only if the last change was more than 24 h ago (R7).
- **Errors**:
  - `INVALID_TIMEZONE`
  - `TIMEZONE_CHANGE_TOO_SOON`
